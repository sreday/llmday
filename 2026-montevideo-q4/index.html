Marcos Martinez

From 1 Hour to 10 Minutes: Automating Purchase Orders with AI

Loopstudio
A US enterprise food and beverage distributor received about 100 purchase orders a day by email, each client with its own PDF or Excel layout. Eight people spent their full workday reading them and typing them into the ERP, at about an hour per order. We replaced that with an AI workflow built on the Anthropic API. Orders now take ten minutes including human review, with over 90% field-level accuracy, at a fraction of a cent per document. Those eight people now spend their time on client relationships and on improving the product. The model was the easy part. About 80% of the effort went into analysis, architecture and specification, much of it data work: reconciling an ERP and a warehouse that disagreed on the same records, and writing down validation rules that only lived in people’s heads. This talk covers what made the system trustworthy enough to run the business on. On the AI side, structured outputs with per-field confidence scores, human review for the exceptions, per-client evals that catch what an aggregate score hides, and a versioned ground-truth suite that turns every prompt or model change into a measured decision. Around it, the parts most demos skip, integrating with the company’s existing systems and a secure deployment built to live inside an enterprise environment. Attendees will leave with a blueprint for taking an AI workflow from demo to production.... Read more

Carla Marcela Florida Roman

Science at Scale: AWS Infrastructure for Reproducible Scientific Experimentation

Bee Zero
Validating a scientific hypothesis is not just a matter of ideas. It also requires infrastructure capable of running experiments in parallel while ensuring traceability, reproducibility, and cost efficiency. In this talk, we present how we designed an experimental platform on AWS to support real-world academic research at scale. The system enables thousands of experiments to run across multiple datasets, algorithms, and experimental conditions, using elastic compute with AWS Batch, structured storage in Amazon S3, a vector database to organize experimental results, and a centralized dashboard to explore and compare experimental behavior. The scientific use case behind this infrastructure is part of a research effort developed in collaboration with Eduardo Di Santi at the University of Colorado Boulder, exploring the relationship between the geometric structure of data and learning efficiency. The platform was designed to evaluate these types of hypotheses empirically at scale. This talk does not replace the formal academic presentation of the scientific findings, which are currently being reserved for publication. The session focuses on the architecture, design decisions, experimental automation, reproducibility, scalability, and lessons learned from using cloud infrastructure to support advanced scientific research. If you work in research, MLOps, data science, or cloud infrastructure, this talk presents a real-world case study of how AWS can transform a complex scientific question into a robust, scalable, and reproducible experimental platform.... Lucia Hernandez

The User Is Part of the Harness: A Year Running an Agent That Adapts to Cognitive Load

Metodica Digital
Most harness talks optimize for the task. This one optimizes for the human operating it. Two years ago, at 35, I was diagnosed autistic, and it explained something I had been working around for decades: my executive function is inconsistent. Some days I can hold twenty projects; some days I can't answer an email. Tools built for an average user kept assuming I was the same person every day. So I built Digitana, a harness on top of Claude that acts as an external executive function. It is not tuned to do more. It is tuned to load me less. This is a field report from almost 600 numbered working sessions, and how it works: - User state as a control signal. Every morning the harness computes a 0–100 Cognitive Load Index from the phase of my menstrual cycle (hormonal load shifts my energy and focus week by week), meetings, hours already spent with the agent, social load and day of the week. The zone rewrites the agent's operating rules: how many options it offers, how long it answers, and how much it decides without asking. - Memory you can diff, and a harness that learns from use. Sessions, minutes and operational memory live on disk in git, not in a vector DB or inside a provider. The model never changes, but the harness does: every correction becomes a written rule, every session closes with what was learned, and skills update their own instructions from how they were used. Nothing the agent "will remember" exists unless it's persisted. - One agent per project. Fourteen projects, each with its own project-manager agent and a single task board, so delegation is the default and the human only does what only she can do. - Letting an agent act in WhatsApp groups with third parties. Two permission levels, a mention-only trigger, and a fail-closed tool guard: the agent can run the project's scripts and commit locally, but never sends, publishes or deletes on anyone's behalf. The goal of this talk is to show a different kind of value AI can add: beyond making a company more productive, it can also take care of the humans behind it.... Read more

Apps, not chats. Shipping macOS products that run AI models on-device

Karma Digital
Most people meet AI as a chat box. But the models can run as real software on your own machine, doing a job inside an app instead of answering prompts in a thread. This talk walks through shipping macOS products that do exactly that, with the models running entirely on-device: transcription and speaker diarization, screen understanding through an MCP server, voice cloning that reads text in your own voice, and an augmented-reality assistant. Running locally reduces per-inference cost, works offline, and can keep your data private, in exchange for fighting model size, memory, latency, and macOS packaging. We share the honest engineering behind products already in users' hands: which models we chose and why, what worked, what broke, and when local is the wrong call. Apps, not chats.... Read more

AgentOps: The future is here

Nubiral
What if the next leap in efficiency in DevSecOps didn’t come from more tools, but from agents capable of reasoning, coordinating, and executing on our behalf? Agent-based artificial intelligence is no longer just a futuristic promise: it’s already changing the way we design, automate, and scale engineering workflows. In this talk, we’ll explore how AgentOps enables us to take AI agents from an interesting demo to real, governable, and impact-driven architectures. We’ll present agent-based architectures applied to DevSecOps scenarios, demonstrating how to design agents with clear responsibilities, explicit contracts, traceability, and collaboration mechanisms. We’ll also review design patterns for building more robust, reusable, and secure solutions. Attendees will gain a concrete understanding of what AgentOps is, how to start designing useful agent-based architectures, which patterns to apply, and how to turn this trend into a real advantage for technology, product, and business teams.... Mark Pawlikowski & Marcos Novelli Harispe

WorkshopPut Down the Prompt: Set Up, Test, and Break a Production Cluster in Seconds with Reliaburger

Reliaburger
Disclaimer: This is a non-LLM break. Take a deep breath and get a taste of a talk you can usually experience at an SREday Conference. I have never run a Kubernetes cluster. Yes, I said it. Are you still with me? Cool! Over the past five years I talked to thousands of SREs and platform engineers at the conferences I run with my team: SREday, LLMday, PLATFORMday and Conf42. The same story keeps coming back. Before the first container hits production you step into the world of Kubernetes, and then you need to build a whole team just to keep it running. A killjoy for many smaller teams. We started talking with my brother, Miko Pawlikowski, how we could help the community ease some of these pains. Miko has been running platform teams on Kubernetes for 10+ years, leading him to start writing Reliaburger: one Rust binary with the scheduler, gossip, Raft, eBPF service discovery, ingress, mTLS, registry, metrics, logs, GitOps and chaos testing inside, driven by TOML (don't worry if those terms sound like alien tech - we'll unpack them together from scratch during the session, it will be fun!). An app with health checks, ingress and autoscaling is twelve lines. He wrote the software. I am here to hand it to the community and see what you do with it. This is a hands-on session, so bring a laptop (macOS on Apple silicon or Linux; Windows is not supported yet). In 30 minutes you will: Install Reliaburger with one command and start a node on your laptop. No container runtime, no root, no VMs: the built-in process runtime runs plain binaries. Deploy an app from a twelve-line TOML file and watch it in the terminal dashboard and the web UI. Ship a deliberately sick version and watch the health checker restart it, then roll back with one command. Break it on purpose with the built-in fault injector: kill an instance, freeze another, and let relish wtf explain what just happened. Read the manual and the source code from inside the binary, so you can keep going after the session. Tell us what broke and what you liked. Reliaburger is free and open source (Apache 2.0), and it is version 0.1, so it will break. That is where you come in. We are looking for helpers, burger ambassadors and contributors: people who will run it, break it, file the issues, write the docs and tell their teams. There are millions of practitioners running parts of Kubernetes they do not need, with more people than they should need to run it. We want this to become a community-driven project, just as our conferences are.... Read more

Martin Rojas

Breaking the GenAI Data Pipeline: Architectural Security and AI-DSPM with OWASP

Cybersecurity Specialist & Auditor
Modern LLM integration frameworks and autonomous agents shatter traditional application security assumptions. By combining system mandates, external context, and user inputs into a single token window—a vulnerability known as the "Flat Namespace"—systems become inherently incapable of distinguishing code instructions from adversarial data payloads. Aimed at senior platform engineers and developers, this condensed 30-minute deep-dive bypasses basic prompt engineering to audit the raw underlying GenAI data infrastructure. Guided by the OWASP GenAI Data Security 2026 initiative, we will dissect real-world, high-impact vectors: semantic embedding inversion (reconstructing raw data from pure mathematical vectors), GPU memory cross-context KV cache bleeding, and non-human identity (NHI) escalation in autonomous workflows. Attendees will leave with a practical architectural reference blueprint to establish an effective AI-DSPM (Data Security Posture Management) strategy. We will cover automated token redaction, deterministic vector namespaces, and the essential 90-day checklist to validate data resilience before deployment. Key Takeaways: The Flat Namespace Paradigm: Why traditional perimeter security and model-level guardrails fail to shield the underlying agent infrastructure. Data Pipeline Exploitation: Technical analysis of vector store vulnerabilities, GPU session bleeding, and unmasked telemetry leaks. The AI-DSPM Reference Architecture: A lightweight blueprint for layered peripheral data validation under open-source OWASP criteria.... Read more

Zyte

Federico Novelli

The AI Security Paradox: Quantifying Risk in the Age of LLMs and Agents

Protect Group
As organizations adopt LLMs and agentic systems, security teams are facing a new challenge: how do we turn emerging AI threats into concrete business risk that can actually inform security decisions? Prompt injection, sensitive data exposure, excessive agent permissions, and unsanctioned use of AI tools can introduce risks that are difficult to evaluate using traditional security models. At the same time, organizations cannot respond to every emerging threat by continuously expanding their security budgets. This session explores how to think about AI-oriented cyber risk, from identifying relevant threats and estimating their likelihood and business impact to evaluating whether a security control is worth its cost. We will examine how technical AI risks can be translated into structured risk conversations and financial terms, helping organizations distinguish between risks that require immediate investment and those where simpler controls or accepted risk may be more appropriate. The goal is not to predict the future of AI security, but to provide a way to reason about security decisions as LLMs and agentic systems become part of the enterprise technology landscape.... Leon Achata

RAG Is Not a Search Problem

TCS
Modern RAG systems are often reduced to a simple pipeline: embed documents, perform vector search, retrieve the top-k chunks, and send them to an LLM. In practice, retrieval is rarely that simple. Exact identifiers, technical terminology, semantic paraphrases, lost document context, and multi-step questions can all expose weaknesses in a purely vector-based approach. This talk explores how modern retrieval systems move beyond basic semantic search through hybrid retrieval, combining sparse and dense methods, contextual retrieval, reranking, query decomposition, and adaptive or agentic retrieval. Rather than presenting a single “best” architecture, we will examine the trade-offs between relevance, recall, latency, cost, and complexity, and look at when each technique is actually useful. The central idea is simple: a RAG system does not need to find the most similar chunks; it needs to retrieve the right evidence for the question. We will build this idea step by step and show how retrieval quality, rather than simply choosing a more powerful LLM, can determine the quality of the final answer.... Read more

Marcelo B San Martin

The Great AI Role Rewrite

Blizzard Entertainment
AI is no longer only automating tasks; it is beginning to rewrite the roles people play at work and in everyday life. As LLMs become collaborators, advisers, tutors, creators, and interfaces to knowledge, the value of many human roles is shifting from producing every output ourselves to directing AI systems, exercising judgment, validating results, and deciding what should not be delegated. This talk explores the changes already visible in software teams, management, education, creative work, and daily decision-making—and what they suggest about the broader societal transformation ahead. It also examines the risks that come with convenience, including weakened critical thinking, blurred accountability, and growing dependence on systems we do not fully understand. Rather than treating AI as simply another productivity tool, the talk presents it as the beginning of a wider redesign of work, institutions, and human identity. Attendees will leave with a practical framework for deciding what to delegate to AI, what should remain under human control, and which capabilities we need to strengthen as our roles continue to evolve.... Marvik

RAG Is Not a Search Problem
Abstract

Modern RAG systems are often reduced to a simple pipeline: embed documents, perform vector search, retrieve the top-k chunks, and send them to an LLM. In practice, retrieval is rarely that simple. Exact identifiers, technical terminology, semantic paraphrases, lost document context, and multi-step questions can all expose weaknesses in a purely vector-based approach. This talk explores how modern retrieval systems move beyond basic semantic search through hybrid retrieval, combining sparse and dense methods, contextual retrieval, reranking, query decomposition, and adaptive or agentic retrieval. Rather than presenting a single “best” architecture, we will examine the trade-offs between relevance, recall, latency, cost, and complexity, and look at when each technique is actually useful. The central idea is simple: a RAG system does not need to find the most similar chunks; it needs to retrieve the right evidence for the question. We will build this idea step by step and show how retrieval quality, rather than simply choosing a more powerful LLM, can determine the quality of the final answer.
