Sam Currie

heyo.computer
Isolation: Containers, VMs, Namespaces, Oh my!
Abstract

Modern systems increasingly rely on isolation mechanisms—especially with the rise of AI agents and sandboxed execution—but there are many different approaches and they each have different strengths and tradeoffs. We'll cover: • Linux namespaces and cgroups • Node isolates and runtime isolation • Isolation methods commonly used in agent frameworks and harnesses • Containers and container runtimes • Virtual machines and KVM • Architecture-level isolation patterns • Practical tradeoffs and real-world use cases Sam has run production workloads at scale across Kubernetes, containers, VMs, lambdas, Node isolates, and sandboxing platforms like E2B, and will share lessons from deploying these systems in practice.

Bio

Currently CEO of Heyo Computer, previously head of Infrastructure at Flatfile and Obvious.ai. Startup rat, drummer, and search & rescue first responder, now located in Buena Vista Colorado

Zachary Gruenberg

Oasis Security
Post Mcp-Session-Id: Auth and Kill Switches for Stateless MCP Agents
Abstract

The July 2026 MCP spec RC drops the initialize handshake and the Mcp-Session-Id header. If you built session auth, audit trails, or agent kill switches assuming a persistent session existed, that assumption just broke — and most people running MCP-connected agents in production haven’t dealt with it yet. I rebuilt my own agent runtime against this change and will share the details of the shift in architecture with you all.

Bio

Zach Gruenberg started at CyberArk as the company’s first AI SME, then moved to Palo Alto Networks as a CyberArk SME following PANW’s acquisition. He’s now a Solution Architect at Oasis Security, focused on non-human identity and agentic access management. He teaches an online community sharing his technical background and spends his time building and rebuilding his own agent infrastructure to work through the identity and auth problems agentic systems create in production.

Maureese Williams

Disney
What Did Your Agent Actually Do?
Abstract

An agent runs forty steps against a real repository. It reports success. Something breaks in production an hour later. Which step did it? For most agent stacks the honest answer is that nobody knows. The trace is a pile of model outputs describing what the agent believed it was doing, the run isn't reproducible, and re-running it produces a different plan anyway. Three properties fix this, and none of them require a better model. Reliability. The agent's world state comes from deterministic sensors, never from the model's own claims. When the model asserts "tests passed" and the sensor disagrees, that's a logged incident, not a state transition. Across an integration suite spanning six system archetypes, 611 of 611 injected false claims were refused, with zero false refusals on honest ones. Reproducibility. No RNG anywhere, ties broken lexicographically, plans replayed bit-exact from a hash-chained journal. Same input, same plan, every time: 120 of 120 generated systems deterministic, 114 of 114 crash-and-resume runs converging to the same state. Auditability. Every step writes an append-only record containing the full decision table that produced it. Tamper with any of it and the chain breaks (3,894 of 3,894 mutations detected). You can ask the system why it chose an action and get the actual reason, not a rationalization generated after the fact. Long horizons are where this pays for itself. At three steps you can eyeball the trace. At forty, determinism is the only thing standing between you and archaeology. I'll show LEDGER running against a real repository, break it on purpose, and replay the failure bit-exact. Then I'll be specific about the cost: what you give up, where the model still genuinely earns its place, and what this approach cannot do.

Bio

Maureese Williams is an AI/Data Engineer at Disney, building RAG and retrieval infrastructure for production systems, with 5+ years across distributed data and ML platforms on AWS and GCP. Co-author of GATS (Graph-Augmented Tree Search, arXiv:2607.08894), a planning framework that replaces per-step LLM calls with search over a persistent, verified world model, with zero model calls at plan time and zero plan variance. Presented the agent-verification side of this work at DEF CON 34.
