HOT TAKE: We Don’t Need Code Reviews - How AI is Changing the Last Sacred Engineering Ritual

groundcover
Code review is treated as the final safety net of modern software engineering. That assumption is quietly breaking down as AI writes most of our code. In many teams today, LLMs generate refactors, tests, fixes, and migrations. The author reviews the code, runs tests, validates behavior, and understands the change end to end. Then they are still required to perform the sacred ritual of opening a pull request and waiting for approval. Days later, an async human review arrives from someone with less context and worse tooling. The result looks like rigor, but mostly adds delay and shallow feedback. This talk argues that traditional PR review has become theater in an AI-driven workflow. AI tools already catch style issues, missing error handling, security risks, and best-practice violations faster and more consistently than humans. Meanwhile, the failures that actually matter, performance, edge cases, operational impact, are rarely caught by late, asynchronous reviews anyway. Based on real production workflows, the session proposes a shift to AI-assisted self-review - engineers own their changes end-to-end, AI enforces consistency and standards, and human review moves to where it adds real value - design discussions, architecture decisions, and mentorship. If AI has fundamentally changed how we write code, it’s time to change how we decide it’s safe to ship.... Read more

Maureese Williams

What Did Your Agent Actually Do?

Disney
An agent runs forty steps against a real repository. It reports success. Something breaks in production an hour later. Which step did it? For most agent stacks the honest answer is that nobody knows. The trace is a pile of model outputs describing what the agent believed it was doing, the run isn't reproducible, and re-running it produces a different plan anyway. Three properties fix this, and none of them require a better model. Reliability. The agent's world state comes from deterministic sensors, never from the model's own claims. When the model asserts "tests passed" and the sensor disagrees, that's a logged incident, not a state transition. Across an integration suite spanning six system archetypes, 611 of 611 injected false claims were refused, with zero false refusals on honest ones. Reproducibility. No RNG anywhere, ties broken lexicographically, plans replayed bit-exact from a hash-chained journal. Same input, same plan, every time: 120 of 120 generated systems deterministic, 114 of 114 crash-and-resume runs converging to the same state. Auditability. Every step writes an append-only record containing the full decision table that produced it. Tamper with any of it and the chain breaks (3,894 of 3,894 mutations detected). You can ask the system why it chose an action and get the actual reason, not a rationalization generated after the fact. Long horizons are where this pays for itself. At three steps you can eyeball the trace. At forty, determinism is the only thing standing between you and archaeology. I'll show LEDGER running against a real repository, break it on purpose, and replay the failure bit-exact. Then I'll be specific about the cost: what you give up, where the model still genuinely earns its place, and what this approach cannot do.... Read more

Sai Varma Dantuluri

Agents Aren't Users

VotalAI
Most teams secure LLM applications the way they secure software: test before launch, add a guardrail, move on. That model breaks down here. Models get updated, prompts change, tools get added, and an agent that was safe last quarter has a different attack surface this quarter. This talk covers three gaps I keep running into in production AI systems, and what to do about each. First, why red teaming a model has to be continuous rather than a pre-launch gate, including what changed across iterations while testing NVIDIA's Nemotron content safety filter model with their AI engineering team. Second, guardrails. What content filters and safety classifiers actually catch, the failure modes teams assume are covered but aren't, and how to build an evaluation loop that tells you when a guardrail has quietly stopped working. Third, identity, the gap I think is most underestimated. Agents authenticate, hold credentials, call tools, and act on behalf of users, but the identity infrastructure we point at them was designed for humans making individual decisions. Sessions, MFA, least privilege, and audit trails don't map cleanly onto a non-deterministic system that spawns sub-agents and chains tool calls across systems. I'll walk through where that mismatch creates real exposure and what agent-native identity has to look like instead. Attendees will leave with a working model for continuously testing their own LLM and agent deployments, not a threat list.... Read more

Agentic Engineering: The Agent Writes the Code, Not the Process

Kidar
While the industry chases agent reliability through smarter models, most agent failures trace to one design choice: letting the model decide what happens next. I built a software factory where the model only writes the code, while a deterministic controller drives Claude Code and Codex workers through the entire workflow, grounded by executable gates and engineering directives, with every transition, retry budget, and terminal owned by a versioned graph. I'll show the architecture, the failure classes it eliminates by construction, and what adversarial battle-testing taught me about where agent autonomy actually breaks.... Read more

Same input, same plan, every time: 120 of 120 generated systems deterministic, 114 of 114 crash-and-resume runs converging to the same state. Auditability. Every step writes an append-only record containing the full decision table that produced it. Tamper with any of it and the chain breaks (3,894 of 3,894 mutations detected). You can ask the system why it chose an action and get the actual reason, not a rationalization generated after the fact. Long horizons are where this pays for itself. At three steps you can eyeball the trace. At forty, determinism is the only thing standing between you and archaeology. I'll show LEDGER running against a real repository, break it on purpose, and replay the failure bit-exact. Then I'll be specific about the cost: what you give up, where the model still genuinely earns its place, and what this approach cannot do.

Abstract
