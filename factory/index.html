LIVE talk factory - with Claude

Recommended!

The same job as the No Claude, manual tab, but you talk to Claude and it runs the factory for you: it adds the recordings, analyses them, reads the whole day's transcript to find every talk, cuts them, sends them to Descript, exports and writes the YouTube texts. You only do the two checks a person has to do - approving the cuts and reviewing the talks in Descript - and the YouTube upload.

Claude knows the factory through the live-factory skill that comes with the sreday repo, so any teammate's Claude works the same way.

1. One-time setup

  1. Claude Code: install it from https://claude.com/claude-code (the desktop app, or in a terminal npm install -g @anthropic-ai/claude-code) and sign in with your Claude account.

  2. The repos, side by side in one folder (e.g. Documents/GitHub/):

    git clone https://github.com/sreday/sreday.git
git clone https://github.com/sreday/llmday.git        # for LLMday events
git clone https://github.com/sreday/platformday.git   # for PLATFORMday events

  3. The factory itself, once - this one you run yourself, because it asks for your Descript API token (Descript → Settings → API tokens), which should never go through a chat:

    • Mac: bash sreday/live-factory/setup.sh
    • Windows: double-click sreday\live-factory\setup.cmd

  4. Start Claude in the sreday folder: open a terminal there and run claude (or open the folder in the desktop app). Check it with: "Is the LIVE talk factory ready on this computer?" - Claude runs the health check and tells you what, if anything, is missing.

2. Process an event - what to say

Replace the event and paths with yours. Events are named like sreday-2026-london-q1 or platformday-2026-austin-q4; Claude can find the right one if you just say "PLATFORMday Austin Q4".

Step Say to Claude What happens
Launch "Launch the factory." Claude starts the app if needed and opens the workbench (http://localhost:8043) in your browser.
Add "Add the recordings from /Volumes/CARD/DCIM for PLATFORMday Austin 2026 Q4, day 1." (more rooms: "…room 2 is track 2") The files are copied in as a checked, read-only backup. Your originals are never touched.
Analyse "Analyse them." Sound, transcript, stills - free, on your computer. About 35 min for an 8-hour day; Claude runs it in the background and tells you when it's done.
Find the talks "Match the lineup." Claude reads the whole day: greetings, "I'm …", the MC, closing lines, Q&A, pauses, titles and abstracts. It gives you a table of every talk with start, end and anything doubtful, and asks you what only someone who was there knows ("who spoke last?").
✋ Approve Open the workbench (http://localhost:8043), check the flagged cuts, tick them, Save cuts - or tell Claude "approve all" if you trust the table. Nothing goes to Descript before this.
Descript "Run the factory." Claude says how many talks and roughly how many Descript credits (8-30 per talk), then cuts, uploads and edits them. Watch it on http://localhost:8043/status or ask "how is it going?".
✋ Review Watch each talk in Descript, trim the extra footage (30 s before, 60 s after), tick Reviewed in the workbench - or tell Claude "Thomas, Jay and MJ are reviewed". Only reviewed talks are exported.
Export "Export the reviewed talks." Final light MP4s, subtitles, chapters, YouTube loudness.
YouTube "Write the YouTube items." Titles, descriptions and thumbnail links, ready to paste. You upload.

3. Handy things to ask

  • "What's the status of PLATFORMday Austin?" / "Which talks are waiting for my review?"
  • "Why is Daniel flagged?" - Claude reads the flags and the transcript and explains.
  • "Which talks weren't recorded?"
  • "Thomas's end is cut off - redo it with 2 more minutes." - Claude fixes the cut and flags the talk for a redo: it is cut again and uploaded as a fresh composition "Thomas Cameron (redo 2)"; the old one stays in Descript.
  • "Edits are paused - what happened?" - Claude reads the edit reports and tells you what to check in Descript before it resumes.
  • "Publish the status." - updates the Factory logs tab of this page.
  • "Which compositions do I delete in Descript?" - Claude lists the leftovers failed uploads left behind (same name as the talk, so it gives the length of the one to delete).

4. What Claude won't do on its own

  • Approve cuts or mark talks reviewed - unless you tell it to.
  • Touch, move or delete your recordings, or free disk space by deleting things on its own. When your disk is low it offers to clean up junk and cache files: it shows you what they are and how big, and deletes only what you pick.
  • Handle your Descript token or any password.
  • Upload to YouTube.

If something looks off, just describe it - "the sound on Raul's talk is only on the left" - and Claude finds out why.

LIVE talk factory - team manual

Probably slower than manual editing for non-tech people...

Turns the long recordings of a live event (SREday, LLMday, PLATFORMday, PEC, DevOps Not Dead) into one clean, YouTube-ready video per talk. Descript only gets the talks themselves: the breaks, set-up chatter, lunch and Q&A never reach it, which saves about a third of its media hours.

recordings  →  analyse  →  find the talks  →  ✋ you check the cuts  →  cut + Descript edit  →  ✋ you check in Descript  →  export  →  YouTube

Two steps are yours (✋). Nothing is uploaded before you approve the cuts, and nothing is exported before you've looked at each talk in Descript.

This is the No Claude, manual tab. The Factory logs tab shows what the factory has done, live: every computer that runs it publishes its progress - at the end of every job, and during a run whenever a talk is ready for review or finished (at most every 20 minutes) - and the tab checks for news every minute. Publish status in the workbench publishes right away. The same page is on sreday.com/factory, llmday.com/factory and platformday.com/factory; each shows its own brand's events (tick "show the other brands" for all).

This page is the manual for operating the tool. The technical details live in live-factory/README.md in the sreday repo. When the tool changes, this page changes with it - see Changelog at the bottom.

1. One-time setup on your computer

You need: a Mac or a Windows PC with 150 GB free for a full day of recordings, Git, and Python 3.9 or newer (the setup installs the rest).

  1. Get the repos. Put them side by side in one folder, e.g. Documents/GitHub/:

    git clone https://github.com/sreday/sreday.git
git clone https://github.com/sreday/llmday.git          # only if you process LLMday events
git clone https://github.com/sreday/platformday.git     # only if you process PLATFORMday events

  2. Run the setup, once:

    • Mac: bash sreday/live-factory/setup.sh
    • Windows: double-click sreday\live-factory\setup.cmd

    It installs ffmpeg and Whisper (the free speech-to-text that runs on your computer) and asks for a Descript API token: in Descript go to Settings → API tokens → Create. Use the team's Descript account. The token is stored on your computer only, never in git. It also puts a LIVE talk factory launcher on your Desktop.

  3. Check it: the setup ends with a health check. Everything should say OK. You can run it again any time: env/bin/python -m live_factory doctor (Mac) or env\Scripts\python -m live_factory doctor (Windows), from the live-factory folder.

Start the app: double-click LIVE talk factory on your Desktop (or ./run.sh / run.cmd in live-factory). It opens two pages in your browser:

  • Workbench - http://localhost:8043 - where you do everything.
  • Status - http://localhost:8043/status - read-only progress of the whole day; leave it open in a tab.

The workbench opens on the event you worked on last (the events you've started are marked ● at the top of the list), and the address shows it (?event=llmday-2026-austin-q4), so a bookmark or a reload keeps it. Finished events in a repo's past/ folder are listed too. Starting the app again while an older copy is still running replaces that copy; jobs already running carry on.

Before every event, update the repos so the lineup is current: git pull in each repo folder.

2. Process an event, step by step

Events are named <brand>-<folder>, e.g. sreday-2026-london-q1 or platformday-2026-austin-q4 - the folder name from the site repo. Pick the event in the dropdown at the top of the workbench.

Step 1 - Add the recordings

In the workbench, open 1. Recordings → Add recordings:

  1. Paste the path of the recording, or of the folder on the SD card / drive that holds them, one per line.

    • Mac: drag the file into the Terminal to get its path, e.g. /Volumes/CARD/DCIM/day1.mp4.
    • Windows: Shift + right-click the file → Copy as path. 2. Pick the Day, and the Track (the room) when the day had more than one room. A one-room day needs only the day. 3. Leave read in place off: the recording is then copied into the factory's folder as a checked, read-only backup. Tick it only when the file is on a drive that stays plugged in and you don't want a second copy - then that file is the only copy, so back it up.

  2. Press Add.

The factory never changes, moves or deletes your original files. If the disk doesn't have room for the whole job (about 2× the recordings), it refuses to start and tells you how much to free - with a red banner and a desktop notification.

Step 2 - Analyse

Press Analyse recordings. On your computer, for free, it:

  • copies the recording in and checks the copy,
  • measures the sound per second (and finds a recording that has sound on one side only),
  • writes a transcript with Whisper,
  • takes stills.

An 8-hour day takes about 35 minutes on an M1/M2 Mac (faster on a PC with an NVIDIA card). You can watch it on the Status page and close the browser - it keeps running.

Step 3 - Find the talks

Two ways:

  • Automatic: press Draft cuts. The factory matches the recording to the lineup: the speaker's "Hi, I'm Dan", the MC's "please welcome…", greetings, the closing "thank you", the Q&A, the pauses. On our first real day it got 13 of 15 talks within 30 seconds and spotted the no-show.

  • With Claude Code (best results): press Brief for Claude, then ask Claude: "match the lineup for platformday-2026-austin-q4". Claude reads the whole transcript, checks frames at every boundary, and writes the cuts.

Either way, the result is a list of cuts, one per talk, waiting for you.

Step 4 - ✋ Check and approve the cuts (gate 1)

Section 2. Cuts in the workbench, one tab per track:

  • The player shows the recording; the waveform under it shows the left channel above the line and the right channel below (a one-sided recording shows only half). Click the waveform to jump there. Cuts are shaded - green once approved.

  • For every cut:

    • ▶ start plays from the cut's start, ▶ end plays its last 15 seconds.
    • −5 −1 +1 +5 nudge a time by seconds; ⇤ / ⇥ set the start / end to where the player is now.
    • words shows what is said around the start and the end.
    • + part - when a talk continues into the next recording file.
    • The talk's name can be changed with the dropdown (a swapped slot).
    • Read the flags (⚑, red) - they are why you're here: very quiet or distorted sound, sound dropping out, too few words, the picture blank, much shorter or longer than its slot, or "sounds like X's talk - swapped slot?".

  • Under the list: Not cut (not recorded properly, or a no-show) and talks neither cut nor skipped. Check these with whoever ran the room.

  • Tick the checkbox of every cut you're happy with. Approve all unflagged ticks the clean ones; flagged and low-confidence cuts must be ticked one by one, on purpose.

  • Press Save cuts.

You don't need to be precise to the second: every clip gets 30 seconds of extra footage before and 60 after, so you can trim it exactly in Descript. A cut must not miss part of the talk, though.

Step 5 - Cut and edit in Descript

Press Run. For every approved talk the factory:

  1. cuts it out of the recording (fixing sound that is on one side only, and zooming in slides that sit in black bars),
  2. uploads it to the event's Descript project (e.g. PLATFORMday Austin 2026 Q4), named after the speaker,
  3. has Descript's AI editor apply Studio Sound 80%, a limiter, the volume, remove the um / uh sounds (only those - real words are kept) and shorten pauses longer than 2 s to 1 s.

Then it stops and waits for you. Two talks go at a time; a day of 15 talks takes about an hour. Each edit costs about 8-30 Descript AI credits - the Status page shows the total.

Step 6 - ✋ Review in Descript (gate 2)

Open the event's project in Descript (link on the Status page). For every talk:

  1. Trim the extra footage: the workbench shows where the talk is inside the clip - "talk runs 0:30 → 25:12 in the clip". Remove what is before the talk and after it (the MC, the Q&A, the next set-up).

  2. Watch / skim it: the sound, the start and the end, the cuts around removed filler sounds.

  3. Back in the workbench, section 3. Talks in Descript, tick Reviewed.

Something wrong with a talk (cut off, wrong talk, bad zoom)? Fix its cut in section 2 if needed and save, then in section 3 type what's wrong and press flag for redo. On the next Run it is cut again and uploaded as a fresh composition, e.g. "Thomas Cameron (redo 2)" - the old one stays in Descript untouched, so you can compare.

Step 7 - Export

Press Run again. Every talk ticked Reviewed is: published from Descript → downloaded → subtitles (SRT) → YouTube chapters → trimmed to the first and last word → set to YouTube loudness (-14 LUFS) → saved as a light MP4 → checked.

The finished videos are in the event's folder, Desktop/video factory - <event>/final videos for YouTube/, named <speaker> - <Event>.mp4. The event folder (button Event folder) has YouTube items.txt.

Step 8 - YouTube

For each talk, YouTube items.txt has, ready to paste:

  • the title: <talk title> | <speaker> | SREday London 2026 Q1 (at most 100 characters),
  • the description in the channel's usual format (event and date, tickets link, CFPs link, chapters),
  • the thumbnail link - the website already draws it; download and upload it.

Upload to the brand's channel as usual. Then put the YouTube link in the event's sheet (the YouTube column) - in the Google Sheet, never in the repo's CSV.

3. When something goes wrong

What you see What to do
Red banner Not enough disk space Free the space it names, or set work_root: D:/live-factory (a bigger drive) in live-factory/settings.local.yml. Nothing was started, or the talk named in the banner stopped before writing its file - run again and it carries on.
Banner Delete in Descript - leftovers of failed uploads A failed upload left a composition with the talk's name - an empty 6 s one, or an unedited full-length twin. Delete the one with the length shown; the real, edited talk is the other one. The factory can't delete it itself (Descript doesn't allow it).
A talk is failed at upload Press retry next to it. A dropped connection is retried 3 times automatically first.
EDITS PAUSED in the log The factory stopped all edits because a report looked like the AI editor touched another talk, or one edit cost too much. Check that talk in Descript; if all is fine, clear the pause - env/bin/python -m live_factory unpause <event> in the live-factory folder (Windows: env\Scripts\python) - then Run.
Descript says 402 The Descript plan is out of credits or media minutes. Top it up, then Run - finished steps are never paid for twice.
A talk's sound is on one side only Nothing - the factory fixes it (it copies the live side to both).
The wrong talk got a name, or a talk is missing Fix it in step 4 (change the name, add a cut with + cut at the playhead), or flag it for redo in step 6.
A talk wasn't recorded It shows under Not cut. Tell the speaker; there is nothing to process.
The workbench doesn't open Double-click the launcher again; if the page is still blank, run doctor (step 1.3).
The run and the workbench stopped with no error Something outside the factory closed them (it happened once in Dallas). Open the workbench again and press Run: it carries on where it stopped, and an edit Descript already finished is not paid for again.
A stretch of a talk has no sound at all In a Zoom recording, the room mic was muted in Zoom. The file can't bring it back - look for another recording (a phone, a camera, the Zoom cloud recording).
You started a job and closed the browser That's fine - jobs run in the background. Reopen the workbench to see them.

One computer per event. Two people processing the same event at once would fight over the Descript project. Agree who runs which event.

4. Where things are

On the computer that runs the event, one folder per conference on the Desktop, e.g. Desktop/video factory - LLMday Austin 2026 Q4/, so several events can run side by side:

Folder / file What's in it
in/ the backup copies of the recordings (read-only - never edit or delete)
rec/ the analysis: transcripts, sound levels, stills
cuts/ the talks as cut and uploaded to Descript
out/, srt/ Descript's downloads, subtitles
cuts.json the cuts you approved (step 4)
YouTube items.txt titles, descriptions, thumbnails (step 8)
final videos for YouTube/ the finished videos of this event

When an event is published on YouTube and the raw recording is backed up elsewhere, the event folder can be archived or deleted to free space - ask first, the in/ copy may be the only backup of the recording.
