LIVE talk factory - with Claude

Recommended!

The same job as the No Claude, manual tab, but you talk to Claude and it runs the factory for you: it adds the recordings, analyses them, reads the whole day's transcript to find every talk, cuts them, sends them to Descript, exports and writes the YouTube texts. You only do the two checks a person has to do - approving the cuts and reviewing the talks in Descript - and the YouTube upload.

Claude knows the factory through the live-factory skill that comes with the sreday repo, so any teammate's Claude works the same way.

1. One-time setup

  1. Claude Code: install it from https://claude.com/claude-code (the desktop app, or in a terminal npm install -g @anthropic-ai/claude-code) and sign in with your Claude account.

  2. The repos, side by side in one folder (e.g. Documents/GitHub/):

    git clone https://github.com/sreday/sreday.git
git clone https://github.com/sreday/llmday.git        # for LLMday events
git clone https://github.com/sreday/platformday.git   # for PLATFORMday events

  3. The factory itself, once - this one you run yourself, because it asks for your Descript API token (Descript → Settings → API tokens), which should never go through a chat:

    • Mac: bash sreday/live-factory/setup.sh
    • Windows: double-click sreday\live-factory\setup.cmd

  4. Start Claude in the sreday folder: open a terminal there and run claude (or open the folder in the desktop app). Check it with: "Is the LIVE talk factory ready on this computer?" - Claude runs the health check and tells you what, if anything, is missing.

2. Ship an event in one go (autopilot)

Say "Please ship the talks from SREday London 2026 Q1 through the live talk factory" and give Claude the recordings (and the separate sound, if any). Claude does everything else without asking: - it finds the talks and their sharp starts and ends; - it checks the slides and the sound; - it approves the cuts itself; - it runs Descript; - after the export it checks every finished video itself, in place of your review in Descript: its first and last words heard again, no silent stretch, no black picture, loudness, length; - it uploads each checked talk to the brand's YouTube channel.

On YouTube, each talk gets: - its title, description and chapters; - the website's thumbnail and the subtitles; - a place in the event's playlist, in the order of the schedule; - a schedule: private, public exactly 5 weeks after the event at 09:00 local time.

Claude also puts each link into the event's sheet (the website shows the video only from that day). Then it writes ship report.md and a postmortem: - what is on YouTube and when it goes public; - which talks are missing and why; - which are problematic and what would fix them; - the Descript credits, and the leftover compositions for you to delete.

It goes in two parts. First, while you're there (about an hour after the recordings are in), Claude makes every decision: which talk is which, the exact start and end of each, the slides. Then it starts one long job and says "you can put the laptop down". Leave it plugged in with the lid open: the factory keeps the computer awake by itself, but a closed lid or an update restart still stops it. Through the night the job: - cuts, edits, exports, proofreads, checks and uploads every talk; - tries again whatever failed for a passing reason; - waits for YouTube's next day if its daily limit is reached.

Talks that are fine are shipped. Talks that are very likely fine but have something to look at (an unsure match, a long pause, a short blackout) are shipped too, and listed under "Please check" - they stay private until the release date, so there is time to watch them. Talks that can't be shipped (not recorded, sound lost) are left out, not shipped broken. When Claude starts the night job, it asks its one question in the same message: whether you have the missing material. It doesn't wait for the answer - everything else is already shipping - and whatever you send later goes in as a follow-up. After that it never stops to ask.

Claude asks you nothing while it runs: every judgment call (an unsure talk, a missing source, a deck from another version) is made by the rules and written into the report. Afterwards, just say what you want: "fetch Kevin's talk from this file", "redo Jay's talk". A talk that isn't sure (its start lost, its sound dying) is never guessed: it waits, and the report says why.

A new computer in one sentence

Install Claude Code (claude.com/claude-code) and sign in with your account. Open it anywhere and paste this, word for word:

Set up the LIVE talk factory on this computer: clone https://github.com/sreday/sreday into Documents/GitHub and follow live-factory/SETUP.md

That's all. Claude installs whatever is missing (Git, Python, ffmpeg), clones the brand repos, installs the factory, signs it in from your Drive, checks it and opens the progress page. The only thing it may ask: to turn on the Google Drive connector (claude.ai > Settings > Connectors). Later, on a computer that already has the repo, you can also start Claude Code in the sreday folder and say "set up the factory on this computer". Claude clones the other brand repos, installs everything (live-factory/bootstrap.py - no questions), fetches your sign-ins from your private Drive vault through your Claude account's Drive connector (the YouTube channels and the Descript token - no API key to type), and runs the health check. Needed on the computer: Git, Python 3.9+, Claude Code signed in with your account (with the Google Drive connector on).

The vault is one file, live-factory vault.json, in your owner-only Drive folder "Claude (private)". Claude keeps it current whenever a sign-in changes. To revoke everything at once: Google account > Security > third-party access ("Conf42 factory"), and Descript > Settings > API tokens.

Launch checklist: once per computer (by hand, or what Claude checks)

Do these once on every computer that ships events, Mac or Windows. Ask Claude "Is the factory ready to ship ?": it runs the checks and tells you what is missing. A run that starts without them stops at the first missing piece.

  1. The repos, side by side in one folder (e.g. Documents/GitHub/), all up to date with git pull. The factory is in the first one; each event's lineup comes from its own brand's repo. 
    git clone https://github.com/sreday/sreday.git
git clone https://github.com/sreday/llmday.git
git clone https://github.com/sreday/platformday.git
git clone https://github.com/Prompt-Engineering-Conference/2026.promptengineering.rocks.git
  2. Python and ffmpeg.
    • Mac: brew install python ffmpeg.
    • Windows: Python 3.12 from python.org (tick "Add to PATH"), and winget install Gyan.FFmpeg.
  3. The setup, by you (it asks for your Descript API token, which never goes through the chat): bash sreday/live-factory/setup.sh on the Mac, or double-click sreday\live-factory\setup.cmd on Windows.
    • Run it again after every update that changes requirements.txt; the 2026-11-27 update added tzdata and pillow. Otherwise doctor says "Python packages: missing".
  4. YouTube, once per channel, by you:
    • You need to be the channel's owner or manager: an editor can't sign the factory in (PEC, for now).
    • You need the OAuth client file of the Google Cloud project "Conf42 factory" (a "Desktop app" client, JSON). Copy it to the computer yourself, from the private folder, e.g. to ~/.claude/private-work/youtube-client.json. Never put it in a repo or a chat.
    • Then, in Claude Code (on Windows use env\Scripts\python in place of env/bin/python): 
      ! cd sreday/live-factory && env/bin/python -m live_factory youtube-login sreday ~/.claude/private-work/youtube-client.json
      On Google's "Choose an account or brand account" screen, pick the SREday channel itself, not your own account. Past the "unverified app" warning, use Advanced. Then do the same for llmday, platformday and pec.
    • The sign-in stays on that computer only, in ~/.live-factory/youtube/, outside every repo. A channel other than the brand's is refused.
  5. Claude Code on this computer, signed in - it proofreads the subtitles before they go to YouTube (on your subscription, no API key). doctor shows "Claude Code (transcript proofread)".
  6. The health check: "run the factory doctor". Everything must say OK, and "YouTube sign-ins" must list the brands you ship.
  7. The first run downloads Whisper (large-v3, about 3 GB, into ~/.live-factory/whisper), so it needs the internet and the disk space.
  8. Disk: 150 GB free for a full day: the copied recordings, the cuts, Descript's exports and the finals.
  9. Power: plugged in, with the lid open. While a job runs the factory keeps the computer from sleeping by itself, but a closed laptop lid, a flat battery or an update restart still stop it. On Windows, pause Windows Update for the day.
  10. One folder per computer: always run the factory from the same sreday/live-factory. Its local/ folder keeps the ledger of paid Descript edits, which stops an edit being paid for twice.
  11. One computer per event: the event's work folder, its state and its YouTube record all live on the computer that runs it.

How fast it goes: - A PC with an NVIDIA card (Elephant, RTX 5090): an 8-hour day is analysed in about 15 minutes, and the edges take about 1 minute a talk. - A Mac (M1/M2): the analysis takes about 35 minutes; the edges run on large-v3 too, a few minutes a talk.

The Descript part and the uploads take the same time on either.

Launch checklist: before each event

  1. git pull the brand's repo. The event's metadata.yml must have:
    • start_time with the UTC offset, e.g. "2026-10-23T09:00:00-05:00" - the release date comes from it;
    • city_name, whose time zone must be in the factory's settings.yml (youtube.timezones) - else the release can be an hour off in summer time; Claude adds a missing city;
    • the brand's youtube_url.
  2. The thumbnails exist: open https://<brand>.com/<event>/teasers/ - the YouTube tab must show a picture for every talk. The website draws them; a talk added late needs the site rebuilt first.
  3. The decks came in through the deck dump (/deckdump). Claude also checks this and lists the missing ones.
  4. The recordings, and any separate sound, are on this computer or on a disk plugged into it.
  5. Then say "Please ship the talks from through the live talk factory" and give the paths.

Things to know during a run: - The YouTube limit: about 100 uploads a day per Google project. A big event or two events in one day can hit it; the run says so, and the next run (or "upload ") carries on. - Leftovers in Descript: a failed upload can leave a composition behind. The API can't delete one, so they are listed in the report for you to delete. - The report and the postmortem come at the end. Talks that are missing, problematic or held are named there, each with why.

4. Handy things to ask

  • "What's the status of PLATFORMday Austin?" / "Which talks are waiting for my review?"
  • "Why is Daniel flagged?" - Claude reads the flags and the transcript and explains.
  • "Which talks weren't recorded?"
  • "Thomas's end is cut off - redo it with 2 more minutes." - Claude fixes the cut and flags the talk for a redo: it is cut again and uploaded as a fresh composition "Thomas Cameron (redo 2)"; the old one stays in Descript.
  • "Edits are paused - what happened?" - Claude reads the edit reports and tells you what to check in Descript before it resumes.
  • "Publish the status." - updates the Factory logs tab of this page.
  • "Which compositions do I delete in Descript?" - Claude lists the leftovers failed uploads left behind (same name as the talk, so it gives the length of the one to delete).

5. What Claude won't do on its own

  • Approve cuts or mark talks reviewed - unless you tell it to, or you ask it to ship an event (autopilot, above).
  • Touch, move or delete your recordings, or free disk space by deleting things on its own. When your disk is low it offers to clean up junk and cache files: it shows you what they are and how big, and deletes only what you pick.
  • Handle your Descript token or any password.
  • Upload to YouTube - except when you ask it to ship an event, and then only to the brand's own channel, private until the release.

If something looks off, just describe it - "the sound on Raul's talk is only on the left" - and Claude finds out why.

LIVE talk factory - team manual

Probably slower than manual editing for non-tech people...

Turns the long recordings of a live event (SREday, LLMday, PLATFORMday, PEC, DevOps Not Dead) into one clean, YouTube-ready video per talk. Descript only gets the talks themselves: the breaks, set-up chatter, lunch and Q&A never reach it, which saves about a third of its media hours.

recordings  →  analyse  →  find the talks  →  ✋ you check the cuts  →  cut + Descript edit  →  ✋ you check in Descript  →  export  →  YouTube

Two steps are yours (✋). Nothing is uploaded before you approve the cuts, and nothing is exported before you've looked at each talk in Descript.

This is the No Claude, manual tab. The Factory logs tab shows what the factory has done, live: every computer that runs it publishes its progress - at the end of every job, and during a run whenever a talk is ready for review or finished (at most every 20 minutes) - and the tab checks for news every minute. Publish status in the workbench publishes right away. The same page is on sreday.com/factory, llmday.com/factory and platformday.com/factory; each shows its own brand's events (tick "show the other brands" for all).

This page is the manual for operating the tool. The technical details live in live-factory/README.md in the sreday repo. When the tool changes, this page changes with it - see Changelog at the bottom.

1. One-time setup on your computer

You need: a Mac or a Windows PC with 150 GB free for a full day of recordings, Git, and Python 3.9 or newer (the setup installs the rest).

  1. Get the repos. Put them side by side in one folder, e.g. Documents/GitHub/:

    git clone https://github.com/sreday/sreday.git
git clone https://github.com/sreday/llmday.git          # only if you process LLMday events
git clone https://github.com/sreday/platformday.git     # only if you process PLATFORMday events

  2. Run the setup, once:

    • Mac: bash sreday/live-factory/setup.sh
    • Windows: double-click sreday\live-factory\setup.cmd

    It installs ffmpeg and Whisper (the free speech-to-text that runs on your computer) and asks for a Descript API token: in Descript go to Settings → API tokens → Create. Use the team's Descript account. The token is stored on your computer only, never in git. It also puts a LIVE talk factory launcher on your Desktop.

  3. Check it: the setup ends with a health check. Everything should say OK. You can run it again any time: env/bin/python -m live_factory doctor (Mac) or env\Scripts\python -m live_factory doctor (Windows), from the live-factory folder.

Start the app: double-click LIVE talk factory on your Desktop (or ./run.sh / run.cmd in live-factory). It opens two pages in your browser:

  • Progress - http://localhost:8043 - a plain page: a bar per stage of the day, then a bar per talk, then only what needs you ("Missing recording for X", "X: not uploaded - needs a look"). Leave it open in a tab.
  • Workbench - http://localhost:8043/workbench - where you do everything by hand (cuts, review, redo).
  • Status - http://localhost:8043/status - read-only progress of the whole day; leave it open in a tab.

The workbench opens on the event you worked on last (the events you've started are marked ● at the top of the list), and the address shows it (?event=llmday-2026-austin-q4), so a bookmark or a reload keeps it. Finished events in a repo's past/ folder are listed too. Starting the app again while an older copy is still running replaces that copy; jobs already running carry on.

Before every event, update the repos so the lineup is current: git pull in each repo folder.

2. Process an event, step by step

Events are named <brand>-<folder>, e.g. sreday-2026-london-q1 or platformday-2026-austin-q4 - the folder name from the site repo. Pick the event in the dropdown at the top of the workbench.

Step 1 - Add the recordings

In the workbench, open 1. Recordings → Add recordings:

  1. Paste the path of the recording, or of the folder on the SD card / drive that holds them, one per line.

    • Mac: drag the file into the Terminal to get its path, e.g. /Volumes/CARD/DCIM/day1.mp4.
    • Windows: Shift + right-click the file → Copy as path. 2. Pick the Day, and the Track (the room) when the day had more than one room. A one-room day needs only the day. 3. Leave read in place off: the recording is then copied into the factory's folder as a checked, read-only backup. Tick it only when the file is on a drive that stays plugged in and you don't want a second copy - then that file is the only copy, so back it up.

  2. Press Add.

Sound recorded on its own device (a recorder on the mixing desk, the AV team's laptop - common with a wired set-up, where the camera only has its built-in mic): add those files too, the same way, for the same day. Sound files (.wav, .mp3, .m4a, .flac...) are taken as separate sound by themselves; a video file that should only give its sound goes in with Claude's "…it's sound only" (--sound). After the analysis the factory finds where each piece of sound belongs on the videos by itself - however the files start and stop, whatever their clocks say, even when one device drifts against the other - and every talk it covers gets that sound instead of the camera's. Where the recorder has a hole, was muted or is clearly worse, the camera's own sound stays.

The factory never changes, moves or deletes your original files. If the disk doesn't have room for the whole job (about 2× the recordings), it refuses to start and tells you how much to free - with a red banner and a desktop notification.

Step 2 - Analyse

Press Analyse recordings. On your computer, for free, it:

  • copies the recording in and checks the copy,
  • measures the sound per second (and finds a recording that has sound on one side only),
  • writes a transcript with Whisper,
  • takes stills,
  • places every separate sound recording on the videos (an 8-hour day takes about a minute).

An 8-hour day takes about 35 minutes on an M1/M2 Mac (faster on a PC with an NVIDIA card). You can watch it on the Status page and close the browser - it keeps running.

Step 3 - Find the talks

Two ways:

  • Automatic: press Draft cuts. The factory matches the recording to the lineup: the speaker's "Hi, I'm Dan", the MC's "please welcome…", greetings, the closing "thank you", the Q&A, the pauses. On our first real day it got 13 of 15 talks within 30 seconds and spotted the no-show.

  • With Claude Code (best results): press Brief for Claude, then ask Claude: "match the lineup for platformday-2026-austin-q4". Claude reads the whole transcript, checks frames at every boundary, and writes the cuts.

Either way, the result is a list of cuts, one per talk, waiting for you.

Step 4 - ✋ Check and approve the cuts (gate 1)

Section 2. Cuts in the workbench, one tab per track:

  • The player shows the recording; the waveform under it shows the left channel above the line and the right channel below (a one-sided recording shows only half). Click the waveform to jump there. Cuts are shaded - green once approved.

  • For every cut:

    • ▶ start plays from the cut's start, ▶ end plays its last 15 seconds.
    • −5 −1 +1 +5 nudge a time by seconds; ⇤ / ⇥ set the start / end to where the player is now.
    • words shows what is said around the start and the end.
    • + part - when a talk continues into the next recording file.
    • The talk's name can be changed with the dropdown (a swapped slot).
    • Read the flags (⚑, red) - they are why you're here: very quiet or distorted sound, sound dropping out, too few words, the picture blank, much shorter or longer than its slot, or "sounds like X's talk - swapped slot?".

  • Under the list: Not cut (not recorded properly, or a no-show) and talks neither cut nor skipped. Check these with whoever ran the room.

  • Tick the checkbox of every cut you're happy with. Approve all unflagged ticks the clean ones; flagged and low-confidence cuts must be ticked one by one, on purpose.

  • Press Save cuts.

You don't need to be precise to the second: before cutting, the factory listens closely at both ends of every talk and sets the exact words itself - the speaker's first words to the room (not the MC, not "can you hear me?"), and their last finished sentence before the Q&A, ideally the closing "thank you". The Q&A is always left out. Claude reads each talk's first and last sentence (ends_brief.md in the event's folder) and tells you; a talk whose ends are not sure waits until they are. A cut must not miss part of the talk, though: it should hold the whole talk.

Step 5 - Cut and edit in Descript

Press Run. For every approved talk the factory:

  1. cuts it out of the recording (fixing sound that is on one side only, and zooming in slides that sit in black bars), and makes the picture and the sound the best they can be:

    • the slides, sharp and full screen: wherever the recording shows a page of the speaker's deck - inside PowerPoint's Presenter View, with the taskbar or a headshot over it, or filmed on a small TV in the room - that stretch shows the deck page itself instead. Bullets that appear one by one appear one by one. A live demo, a browser, code or the speaker on stage keep the recording. The deck comes from the deck dump (the talk page's "Download slides" PDF) or from a PDF you drop into the event folder's decks/ named after the speaker;
    • night mode (a yellow, Night Shift screen share): the deck pages have the true colours anyway; what stays video gets its colours put back;
    • the separate sound where there is one (step 1);
    • saturated sound (a mic or recorder driven too hard, every loud word cracking): the factory hears which talks have it and where. Where another track has the same moment clean (the camera next to a clipped recorder, the other channel), it uses that one. With no choice it tries the repair tools on 30 s of the clipped speech, checks the result with speech recognition, and repairs the whole talk with the best one that really helps - that talk then gets the normal Studio Sound. Only when nothing helps does Descript get Studio Sound 100%, the last resort. Ask "which talks have saturated sound?" before the run to see the list; the 30 s tried go to cuts/<speaker>.sound-trial/ for a listen.

    Then the factory checks the cut itself before anything is uploaded (Descript costs money): the deck pages really are in the picture, the separate sound really is in the cut, in sync, and the camera's own "pilot" sound is gone. A talk that fails stops there - no credits spent - and says what is wrong; cuts/<speaker>.check.jpg shows frames of the cut.

    Before the run you can see what it will do: ask Claude "look at the slides for PLATFORMday Austin" - each talk gets a before/after picture cuts/<speaker>.picture.jpg in the event folder. 2. uploads it to the event's Descript project (e.g. PLATFORMday Austin 2026 Q4), named after the speaker, 3. has Descript's AI editor apply Studio Sound 80%, a limiter, the volume, remove the um / uh sounds (only those - real words are kept) and shorten pauses longer than 2 s to 1 s.

Then it stops and waits for you. Two talks go at a time; a day of 15 talks takes about an hour. Each edit costs about 8-30 Descript AI credits - the Status page shows the total.

Step 6 - ✋ Review in Descript (gate 2)

Open the event's project in Descript (link on the Status page). For every talk:

  1. The start and the end are final already - no trimming. Check them: the talk should open on the speaker's first words and end right after their last sentence, with no Q&A. If one is wrong, flag the talk for redo (below) and say what is wrong ("starts on the MC", "ends mid-sentence").

  2. Watch / skim it: the sound, the start and the end, the cuts around removed filler sounds.

  3. Back in the workbench, section 3. Talks in Descript, tick Reviewed.

Something wrong with a talk (cut off, wrong talk, bad zoom)? Fix its cut in section 2 if needed and save, then in section 3 type what's wrong and press flag for redo. On the next Run it is cut again and uploaded as a fresh composition, e.g. "Thomas Cameron (redo 2)" - the old one stays in Descript untouched, so you can compare.

Step 7 - Export

Press Run again. Every talk ticked Reviewed is: published from Descript → downloaded → subtitles (SRT) → YouTube chapters → trimmed to the first and last word → set to YouTube loudness (-14 LUFS) → saved as a light MP4 → checked.

The finished videos are in the event's folder, Desktop/video factory - <event>/final videos for YouTube/, named <speaker> - <Event>.mp4. The event folder (button Event folder) has YouTube items.txt.

Step 8 - YouTube

For each talk, YouTube items.txt has, ready to paste:

  • the title: <talk title> | <speaker> | SREday London 2026 Q1 (at most 100 characters),
  • the description in the channel's usual format (event and date, tickets link, CFPs link, chapters),
  • the thumbnail link - the website already draws it; download and upload it.

Upload to the brand's channel as usual. Then put the YouTube link in the event's sheet (the YouTube column) - in the Google Sheet, never in the repo's CSV.

With Claude, the factory can do all of this itself on autopilot (the "With Claude" tab, "Ship an event in one go"). Each talk is uploaded private and YouTube makes it public exactly 5 weeks after the event at 09:00 local, with its thumbnail, subtitles and the event's playlist. The website shows a talk's video only from that day, so the link can go into the sheet straight away.

3. When something goes wrong

What you see What to do
Red banner Not enough disk space Free the space it names, or set work_root: D:/live-factory (a bigger drive) in live-factory/settings.local.yml. Nothing was started, or the talk named in the banner stopped before writing its file - run again and it carries on.
Banner Delete in Descript - leftovers of failed uploads A failed upload left a composition with the talk's name - an empty 6 s one, or an unedited full-length twin. Delete the one with the length shown; the real, edited talk is the other one. The factory can't delete it itself (Descript doesn't allow it).
A talk is failed at upload Press retry next to it. A dropped connection is retried 3 times automatically first.
EDITS PAUSED in the log The factory stopped all edits because a report looked like the AI editor touched another talk, or one edit cost too much. Check that talk in Descript; if all is fine, clear the pause - env/bin/python -m live_factory unpause <event> in the live-factory folder (Windows: env\Scripts\python) - then Run.
Descript says 402 The Descript plan is out of credits or media minutes. Top it up, then Run - finished steps are never paid for twice.
A talk's sound is on one side only Nothing - the factory fixes it (it copies the live side to both).
The wrong talk got a name, or a talk is missing Fix it in step 4 (change the name, add a cut with + cut at the playhead), or flag it for redo in step 6.
A talk wasn't recorded It shows under Not cut. Tell the speaker; there is nothing to process.
The workbench doesn't open Double-click the launcher again; if the page is still blank, run doctor (step 1.3).
The run and the workbench stopped with no error Something outside the factory closed them (it happened once in Dallas). Open the workbench again and press Run: it carries on where it stopped, and an edit Descript already finished is not paid for again.
A stretch of a talk has no sound at all In a Zoom recording, the room mic was muted in Zoom. The file can't bring it back - look for another recording (a phone, a camera, the Zoom cloud recording).
You started a job and closed the browser That's fine - jobs run in the background. Reopen the workbench to see them.

One computer per event. Two people processing the same event at once would fight over the Descript project. Agree who runs which event.

4. Where things are

On the computer that runs the event, one folder per conference on the Desktop, e.g. Desktop/video factory - LLMday Austin 2026 Q4/, so several events can run side by side:

Folder / file What's in it
in/ the backup copies of the recordings (read-only - never edit or delete)
rec/ the analysis: transcripts, sound levels, stills
cuts/ the talks as cut and uploaded to Descript
out/, srt/ Descript's downloads, subtitles
cuts.json the cuts you approved (step 4)
YouTube items.txt titles, descriptions, thumbnails (step 8)
final videos for YouTube/ the finished videos of this event

When an event is published on YouTube and the raw recording is backed up elsewhere, the event folder can be archived or deleted to free space - ask first, the in/ copy may be the only backup of the recording.
